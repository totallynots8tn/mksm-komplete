## Fixes by mod (audit bug numbers in brackets)

### XP Shop 0.12.0
- **EX cancels (the bug you reported).** 0.11.3 ended the EX move on any
  attack press and dropped the press, so Liu went idle. Now, during an EX move,
  L2 + *another* EX button is held back (the game sees it released), and the
  moment the first move's last event has played (its last hit, or the fireball
  leaving the hand) the move ends and the press is played back as R2 + the
  button, so the next EX starts on the next frame. Early presses and taps both
  work. The *same* button again is the move's own chain (X, X, X) and is left to
  the game. A cancel waits at most 45 frames; no cancel without the stamina, or
  in an anim whose events can't be read. [#4]
- **Slow motion removed again.** 0.11.3 re-added the 8-frame global half speed
  per EX hit, which you had removed for good. [#3]
- **EX purchases back in level slots 19-21.** Evidence: the menu data
  (`analysis/xp_shop/out/mpd_tree.csv`) shows vanilla purchases only write
  slots 0-3 (specials) and 13-17 (combos), and the user's saves never show game
  values in 18-22. Slots 23-26, where 0.11.3 put them, are the game's: `0x1DA00`
  (callers `0xC58C3`, `0xD760E`) lets a co-op player start a team attack when
  any of them is non-zero, and move conditions `0x318E`-`0x3191` test them.
  0.11.3's bytes are moved back on the next load and joined with what was in
  19-21, so **EX moves bought before 0.11.3 count again**. [#1]
- Co-op: only real (message 164) hits of an EX are boosted; the other player's
  hits during your EX aren't. Single player keeps the wider rule (some EX hits
  skip message 164). Values that aren't a hit's damage are never multiplied. [#2]
- L2/R2 are read from the trigger bytes only. 0.11.3 also read joypad +0x28
  and +0x2C, which the game's pad translator (`0x129480`) never reads.
- The EX moves run in their own script (`upgrade_ex.lua`): an EX error can no
  longer switch off Health, Stamina, Weapons and the menu.
- Unchanged on purpose: 5x EX damage (you asked to keep it for dev; toning it
  down for release is the single constant `EXP.DAMAGE`).

### Time Rifts 0.8.0 (+ callgate v1.1)
- **Honest verdicts** [#7]: `BEATEN` when the game sets the boss's health to 0
  (setHealth `0x153CD0`, or actor +0x368 seen at 0); a boss that disappears
  with health left is noted with its health and distance from you, then the
  next boss drops (`VANISHED` after the last); `FAILED` when your health hits 0;
  `LEFT` when the map changes. The report comes one frame after the verdict so
  the cleanup isn't lost.
- **One time per save** (your design): a beaten rift is a bit in player 1's
  level slot 22 (mark 0xA0) and never opens again on that save. To re-test on
  the same save, clear that byte with `tools/livemem/peek.py`.
- No spawn group is built after the map changes; the boss group is emptied
  when the rift ends. [#10]
- The memory slot for the boss prefers a type no enabled spawn group uses.
- Not a bug after all [#10]: writing +0x3217 on entity 1 in single player is
  exactly what the game's own loadmap does (`0xD0E28`, unconditional).
- **callgate v1.1** [#8]: every call is checked when it is queued (argument
  types, frame size against the write budget), so a bad call errors in the
  caller's frame instead of inside the target hook with the vtable redirected.

### Time Rifts × LDK × Shuffle [#9, #6]
- The boss group now carries a "RIFT" word at group record +0xA10. In the
  record's tail the spawn code (`0x1D2xxx`) reads only the count +0xA68 and
  the enabled byte +0xA6A; Time Rifts clears the word when the rift ends and
  only ever clears a word that is still its own. LDK and Shuffle skip a marked
  group. The sim proved the bug: without the mark LDK x3 turned the one boss
  into three.
- **LDK 3.11.1** uses Shuffle's outsider for reinforcements (it never counted
  it, because Shuffle converts entries after both censuses). Sim, one-type
  area like Goro's Lair: extras 77 → 93, failed spawns 28 → 18; two- and
  three-type areas unchanged.

### Shaolin Shuffle 0.11.4 [#5]
- A cutscene evicting the outsider in the same tick as a re-shuffle could need
  up to 288 writes (limit 256: the script switches off). The restore now gets
  its own tick.

### Environmental Kill XP 2.0.1 [#11]
- A victim is paid once until its character slot is freed (checked every
  frame). 2.0 ignored any hazard kill in a slot for 5 s, so new enemies in a
  reused slot (common in LDK crowds) earned nothing.

### Solo Co-op Paths 0.6.3 [#12]
- The plate rewrite runs in single player only (it rewrote trigger conditions
  in co-op and versus too).

### Unlock All 1.1.1
- The readme promised that disabling the mod re-locks the save. False: the
  save routine `0xA0420` (mirror of the profile load `0xA03C0` the mod hooks)
  copies the in-memory unlock bits into the save. The script is unchanged
  (restoring the real bits before saving would also drop anything earned).
